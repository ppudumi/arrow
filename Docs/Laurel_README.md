# 라우랄 (Laurel) — 1~3스테이지 플레이 빌드

Unity **6000.3.25f1 (6.3 LTS)** · URP 2D · 브랜치 `laurel-dev`

## 실행

| 항목 | 위치 |
| --- | --- |
| macOS 빌드 | `Builds/Laurel/macOS/Laurel.app` (git 제외 폴더) |
| Windows 빌드 | `Builds/Laurel/Windows/Laurel.exe`, 배포용 `Builds/Laurel/Laurel-Windows.zip` |
| 에디터 | `Assets/Laurel/Scenes/Laurel_Main.unity` 를 열고 Play |
| 빌드 메뉴 | `Tools > Laurel > Build macOS` / `Build Windows x64 + ZIP` |
| 명령줄 빌드 | `unity build --target StandaloneOSX --execute-method Laurel.EditorTools.LaurelBuilder.BuildMacFromCommandLine .` |
| 저장 파일 | macOS `~/Library/Application Support/DefaultCompany/laurel/laurel_profile.json` (+ `.bak`) / Windows `%USERPROFILE%\AppData\LocalLow\DefaultCompany\laurel\` |

### 자동 검증

```
Laurel.app/Contents/MacOS/laurel -laurelSelfTest -laurelSelfTestOut report.txt
# 재실행 후 저장 유지 검증 (두 번 실행)
laurel -laurelPersistPhase 1 -laurelSelfTestOut p1.txt
laurel -laurelPersistPhase 2 -laurelSelfTestOut p2.txt
```

검증은 실제 사용자 저장 파일 대신 `laurel_selftest_*.json` 을 씁니다. 최근 결과는 `Docs/Laurel_SelfTest_Report.txt`.

## 게임 흐름

1. 타이틀 → **새 게임**: 도입 스토리 → 튜토리얼(신의 힘: 체력 300·공격 6·더블점프·대쉬)
   - 이동·점프·더블점프·대쉬 → 과녁 사격 → 화살 회수 → **거대한 뱀 파에톤**(최대 체력 66: 기본 화살 6발)
   - 튜토리얼 방과 **튜토리얼 직후 첫 전투 방 하나**는 숲·유적 배경 + 어두운 흙갈색 지형(아래 '아트·연출 적용' 참고)
2. 파에톤 처치 → 에로스의 금화살 **저주** → 본게임 기본 상태(체력 100·공격 1·스킬 없음·아폴론+기본 줍기)로 1스테이지 지도
3. 스테이지 = 노드 지도(전투·정예·보상·상점·샘 → 보스). 노드마다 작은 정사각형 방
4. 1스테이지 보스(칼리돈의 멧돼지) → **로비 없이** 2스테이지(아켈로오스) → 3스테이지(에로스) → 결과 화면 → 로비
5. 어디서든 사망 → 사망 화면 → 로비. 재도전은 1스테이지 처음부터, 돈·화살·유물·도전 중 능력치 초기화
6. 로비: 출정 · **넥타르 강화(개미굴)** · 궁술 선택 · 기록 · 수련장(허수아비)
   - 보스 처치 → 해당 스킬 **구매 자격** → 넥타르로 구매 → 영구 보유 (자동 지급 없음)

### 플레이어 파츠 시트 · 화살 선택 카드

- `Assets/pjs/Sprites/Character/player_parts.png`: 기존 캐릭터를 2배 해상도로 다시 그린 파츠 시트. 64 PPU(기존 32 PPU 와 같은 월드 크기), Point 필터·무압축·밉맵 없음을 임포터가 강제한다. 흰 바탕만 투명 처리했고, 손대지 않은 원본은 `Character_Original/player_parts.png`.
- 프리팹에 적용한 파츠: 상의(`Torso`), 머리 3종(조준 아래/정면/위), 팔 3종(활 든 왼팔 · 쏠 때 굽은 오른팔 · 평소 내린 오른팔), 하의 6종(대기 · 점프 상승/낙하 · 2단 점프 회전 · 달리기 3프레임), **흰 활(`Bow`)·흰 화살통(`Quiver`)**. 전환은 `Scripts/Combat/PlayerPartsAnimator`. 다리는 치마에 가려 렌더러만 끔.
- 흰 활: 시트의 조각 이름을 `Ribbon` → `Bow` 로 바로잡음(임포터의 `Renamed` 표가 spriteID 를 이어받아 참조 유지). 원본에서 배경 제거 때 지워졌던 활 안쪽 흰색을 `Character_Original` 에서 복원(활 영역 223px만). 피벗 = 손잡이 중심. 프리팹에서 손끝(0.22, 0)에 붙이고 **45° 회전**해 정면 조준 시 세로로 섬. 정면·위·아래 조준 모두 손과 손잡이 거리 0.1px
- 흰 화살통: 시트 그림이 다른 파츠보다 약 3배 크게 그려져 있어 1/3 크기로 사용(허리 왼쪽, 가로)
- 겹침 순서: 머리 7 > 활 쥔 팔 6 > 활 5 > 화살통 4 > 하의 2 > 상의 1 > 굽은 오른팔 −1 > 허리 리본 −3/−4. 조준 각도에 따른 순서 전환(`armOrderHigh/Low`)은 둘 다 5로 두어 끔
- 허리 리본(`ProceduralWaistRibbon.sortingOrder`): 3 → −3 으로 옷 뒤에 그림
- 아직 없음: 활 시위, 오른팔·어깨 위치 조정(보류)
- 화살 선택 카드(보상·상점): `Scripts/UI/ArrowCardArt` 가 금색 장식 테두리 픽셀 아트를 런타임에 그리고 `GameUI.DrawArrowCard` 가 이름 / 능력 설명 / 보유 수량(현재 덱의 같은 화살 수)을 표시한다.
- `Docs/DesignReference/arrow_selection_reference.png`: 카드 분위기 참고 이미지. 게임 에셋이 아니며 빌드에 포함되지 않는다.

## 아트·연출 적용 (튜토리얼 · 첫 전투 방 · 로비)

모든 설정은 `Laurel_Main.unity` 의 오브젝트 Inspector 에서 바꾼다. 방은 런타임에 만들어지므로 값은 **Play 를 다시 시작하면** 반영된다(배경 이미지 값은 플레이 중에도 바로 반영).

### 어디에 무엇이 적용되나

| 방 | 배경 | 지형 모양 | 장식 |
| --- | --- | --- | --- |
| 튜토리얼 (`Room_Tutorial`, 보스전 포함) | `Backdrop_Tutorial` (숲·유적) | `TerrainStyle_Tutorial` | — |
| 튜토리얼 직후 **첫 전투 방 하나** (`Room_S1_N0` 또는 `Room_S1_N1`) | `Backdrop_Tutorial` | `TerrainStyle_Tutorial` | — |
| 로비 (`Room_Lobby`) | `Backdrop_Lobby` (지하 신전) | `TerrainStyle_Lobby` | `LobbyDecor` |
| 그 밖의 모든 방 | 기존 임시 단색 배경 | 기존 단색 지형(한쪽 통과 발판) | — |

- 연결: `GameRoot` Inspector 의 `Tutorial Backdrop` / `Tutorial Terrain Style` / `Lobby Backdrop` / `Lobby Terrain Style` / `Lobby Decor`. 비우면 그 방은 예전 모습으로 돌아간다.
- 첫 전투 방 한정 방법: `StartRun(fromCurse: true)`(파에톤 처치 → 저주 직후)일 때만 `GameRoot.PendingTutorialLookCombat` 를 켜고, `EnterNode` 가 첫 전투 방을 만들 때 소모한다. 로비에서 시작한 도전에는 적용되지 않는다. 1스테이지 첫 층은 항상 `CC` 라 첫 방은 늘 전투 방(발판 배치 0~3 무작위).

### 카메라 (`Main Camera` → `Camera Rig`)

| 값 | 현재 | 의미 |
| --- | --- | --- |
| `Play Size` | 7 | 일반 방 줌(화면 세로 절반). 0 이면 `balance.json → world.cameraSize`. 보스전은 `bossCameraSize` 9 |
| `Look Up` | 2 | 플레이어보다 위를 비춤(이전 1.2) — 위쪽 발판이 한 단계 먼저 보임 |
| `Look Ahead` | 2.5 | 달리는 방향 앞을 미리 비춤(방이 화면보다 넓을 때만 효과, 예: 로비) |
| `Fall Look Down` / `Fall Speed Threshold` | 2.5 / 8 | 빠르게 떨어질 때 아래 착지점을 미리 비춤 |

- 줌을 8 로 빼는 안도 비교했지만, 22칸 방은 줌 7 에서 이미 가로 전체가 보여 벽 바깥만 더 보이고 캐릭터만 작아져서 7 유지.
- `CameraRig` 는 씬의 Main Camera 에 붙어 있고 `GameRoot.Awake` 가 `Init()` 으로 먼저 초기화한다.

### 배경 이미지 (`RoomBackdrop`)

- 필드: `Image`(PNG), `Width`(월드 폭, 세로는 비율), `Offset`(방 중심 기준), `Parallax`(0=방 고정, 1=화면 고정), 이미지 위·아래 바깥 채움색과 경계 그라데이션.
- 붙는 순간 그 방의 임시 배경(`BgFar`·`Bg`·`Deco`·로비 `Pillar`)을 숨긴다.
- `Backdrop_Tutorial`: `Art/Backgrounds/Tutorial_Backdrop_TEMP.png`(숲 콘셉트아트에서 캐릭터·발판·화살·검은 빈 공간이 없는 위쪽 1230×505만 잘라 냄). 폭 34(보스 줌 9 의 화면 폭 32 보다 넓게), Parallax 0.6, 아래는 안개색으로 섞임.
- `Backdrop_Lobby`: `Art/Lobby/Lobby_Backdrop_TEMP.png`(지하 신전 콘셉트아트에서 공중 발판 3개·제단·올리브 덤불·플레이어를 주변 배경으로 메운 것). 54.3px = 1유닛, 그림 바닥선 = 로비 바닥(y −7), Parallax 0(기둥 장식과 정확히 겹치도록 고정).

### 지형 모양 (`TerrainStyle`)

| 값 | 튜토리얼·첫 전투 방 | 로비 |
| --- | --- | --- |
| `Platform Thickness` (보이는 두께, 윗면 고정·아래로 늘어남) | 1.2 (이전 0.6 의 2배) | 0.6 |
| `Solid Platforms` | 켬: 충돌체 = 보이는 몸체(윗면 착지, 밑면·옆면 막힘), 한쪽 통과 효과 없음 | 끔: 기존 한쪽 통과 발판(충돌 0.6) |
| 몸체 / 테두리 / 착지면 띠 | `#130B04` / `#6E5741` / `#7A6957` (숲 지형 콘셉트아트) | `#2A1E29` / `#5A403A` / `#E9B06A` (어두운 석재 + 밝은 착지면) |
| 테두리·띠·안쪽 그라데이션 | 0.05 / 0.1 / 0.1(진하기 0.55) | 0.05 / 0.12 / 0.12(0.5) |
| `Style Outer Blocks` | 켬 | 켬 |
| `Mask Outside Walls` / `Outside Mask Size` | 켬 / 500 | 켬 / 500 |

- 테두리는 월드 유닛 고정 두께라 블록 크기와 상관없이 같은 굵기. 외곽 블록(바닥·벽·천장)은 플레이 공간 쪽 면에만 그리고, 바닥 띠·천장 테두리를 벽 테두리 두께만큼 늘려 안쪽 모서리가 끊기지 않게 함(이중 테두리 없음).
- 외벽 바깥 가림: 좌우 외벽 바깥면에서 0.1 안쪽부터 500×500 몸체색 사각형(충돌 없음, 정렬 6 = 배경보다 앞). 보스 줌 9 × 32:9 화면(중심에서 ±32.5)까지 덮음을 확인. 천장 위·바닥 아래는 화면 흔들림 때만 최대 0.5 보이며 가리지 않음(튜토리얼).

## 전투 HUD (튜토리얼 · 모든 전투 방 공용)

`Scripts/UI/GameUI.CombatHud.cs` (`GameUI` partial). 상태가 `Tutorial`·`Node`(전투·정예·보스 방)일 때와, 그 위에 대화가 뜰 때 같은 HUD 를 그린다. **로비는 HUD 없음**: 중앙 메뉴(출정·넥타르 강화(보유량)·궁술 선택·기록·타이틀로)와 그 아래 수련장 안내만(`DrawLobby`). 예전 로비용 HUD(`DrawHud`)는 삭제. 로비에서도 이동·발사·회수·허수아비 연습은 그대로.

왼쪽 위, 위에서 아래로:

1. **맵 이름** — 패널 없이 외곽선 글자. 현재 방의 실제 이름(`Room.Theme.name`: 튜토리얼 '델포이 신전 앞', 1스테이지 '델포이 숲' …) + 작은 부제(튜토리얼 / `n스테이지 · 노드 종류 · 층`). 매 프레임 현재 방을 읽어 방이 바뀌면 바로 갱신.
2. **체력 용기** — 콘셉트(`raurel-hud-concept.png`)의 원형 유리 용기·코르크·붉은 액체를 48px 픽셀 아트로 런타임 생성(×3). 붉은 액체가 `현재/최대` 비율만큼 **아래부터** 차고(용기 안쪽 원 기준), 피해·회복 시 초당 1.5 비율 속도로 부드럽게 내려가거나 올라감. 가운데에 실제 `현재 체력 / 최대 체력`.
3. **골드 · 넥타르** — 체력 오른쪽에 가로로 `금괴 아이콘 + 수량`, `보랏빛 작은 암포라 아이콘 + 수량`. 두 아이콘은 같은 픽셀 배율(×3)·같은 윤곽색. 수량은 `Run.gold`, `Profile.nectar` 를 매 프레임 읽음.
4. **퀘스트** — 체력·재화 줄 바로 아래. 현재 목표와 체크(✔/□). 튜토리얼: 단계별(이동·점프·더블점프·대쉬 → 과녁 3개 → 화살 회수 → 파에톤). 전투 방: '모든 적 처치 (남은 적 n · 웨이브 a/b)', 보스 방: '○○ 쓰러뜨리기'. 목표가 없으면 패널을 그리지 않음. 배경은 **양피지**(`Art/UI/Quest_Parchment.png`, `GameRoot → Quest Parchment` 에 연결, 최대 512px·읽기 가능으로 임포트). 9-slice(가장자리 왼50·오른80·위62·아래46px 고정)라 목표 수에 따라 높이가 바뀌어도 말린 모서리·올리브가 찌그러지지 않음. 제목·체크리스트는 짙은 갈색(완료: 올리브색 ✔ + 흐린 갈색), 글자는 말린 모서리·올리브를 피한 여백(왼54·오른86·위24) 안. 밝은 양피지 위 어두운 글자가 Linear 합성에서 흐려져서 굵게 + 겹쳐 그림(`InkText`).

- 오른쪽 위 발사·회수 상태 패널은 그리지 않음(발사·회수 기능은 그대로). 그 자리에 유물 목록.
- 하단 화살통(`GameUI.Quiver.cs`, 시안 `raurel-quiver-concept.png`): 예전 화살통과 **같은 자리·크기**(아래에서 128, 높이 108 — 플레이 화면을 가리지 않음)에 짙은 갈색 패널 + 탁한 갈색 테두리, 제목 `화살통 n/전체`, 회색 카드(74×68)에 대각선 도트 화살 아이콘(16px ×2.5)과 왼쪽 아래 카드 피해. 다음에 발사할 맨 왼쪽 카드만 탁한 노란색. 왼쪽 띠 = 화살 고유색, 아래 띠 = 희귀도 색. 기본 화살은 시안 색, 특수 화살은 같은 도트 화살을 고유색으로 칠함(전용 그림 없음). 순서·수·피해는 실제 화살통을 매 프레임 읽음(발사=맨 앞 빠짐, 회수=맨 뒤). 오디세우스 충전 막대는 기존 그대로.
- **적 체력 숨김**: `GameUI.ShowEnemyHealth = false`. 적 머리 위 체력바(`DrawWorldOverlay`, 튜토리얼 과녁·일반·정예·로비 허수아비)와 화면 위 보스 체력 패널(이름·패턴·막대, 배경째 — 전투 HUD 와 로비용 기존 HUD 두 곳)을 그리지 않는다. 적 체력 데이터·피해 계산·페이즈·사망, 플레이어 체력, 타격 피해 숫자, 정예·상태이상 표시, 박힌 화살 수는 그대로. 다시 보이게 하려면 이 값을 true.
- '전투 기록' 버튼과 기록 패널은 **삭제**(2026-11-06, 사용자 지시). 화면 표시 전용이었고 파일로 저장되지 않았음. 전투 로그 수집(`PlayerCombat.Log`/`LogLines`)은 코드에 남아 있지만 화면에는 보이지 않음.
- 콘셉트의 화살(TAB)·지도(M) UI 는 범위 밖이라 넣지 않음.
- **Linear 색 공간 보정**: 이 프로젝트는 Linear 라 IMGUI 가 색을 밝게 바래 보이게 한다. 새 HUD 의 픽셀 아트와 퀘스트 패널 색은 미리 선형값으로 바꿔 넣어(`ForScreen`, `ScreenColor`) 의도한 색(액체 `#9C141E`, 금괴 `#F2C230`, 암포라 `#8E5BD6`)으로 보인다. 글자 외곽선은 불투명 검정. 기존 다른 화면(로비·상점 등)의 패널은 보정하지 않아 여전히 밝게 보임.
- 검증(Play 모드, 코드 값): 튜토리얼·일반 전투가 같은 `DrawCombatHud` 사용. 체력 100%·50%·0% 에서 액체가 가득·절반·비어 있음(캡처 확인, `FlaskFillV` 0→0.104, 0.5→0.458, 1→0.813 = 안쪽 원 바닥~꼭대기). 골드 123·넥타르 45 로 바꾸면 그대로 표시, `AddGold`·`AddNectar` 로 늘리면 즉시 갱신. 방 이름 '델포이 신전 앞' → '델포이 숲', 퀘스트가 튜토리얼 체크리스트 → '모든 적 처치 (남은 적 2 · 웨이브 1/2)' → 처치 후 ✔. HUD 전용 기존 자동 테스트는 없음.

## 회수 이펙트 (오르페우스 '부르기')

- 대상: R 을 누르고 있으면 바닥 화살이 5초에 걸쳐 돌아오는 **오르페우스 — 부르기**(`OrpheusCall`, 튜토리얼 회수 방식).

Point 필터·무압축·밉맵 없음. 64 PPU(플레이어 파츠와 같은 픽셀 크기, 1.75×1.16 유닛), 정렬 8(플레이어 파츠 앞·화살 뒤), 플레이어 몸 중심(`PlayerCenter`)을 따라감.
- 코드: `Scripts/Combat/RecallFx.cs`, 연결은 `OrpheusCall.Tick`. **R 이 눌려 있고 부르기로 실제 돌아오는 화살이 있을 때만** 표시. R 을 떼면(돌아오던 화살이 떨어짐)·마지막 화살 회수·라운드 종료(회수 방식 `Dispose`)·입력 잠김 시 정리. 이펙트는 회수 방식 객체당 하나만 만들어 재사용(연속 입력에도 1개).
- 다른 회수 방식(기본 줍기·데메테르·제우스 등)은 R 을 눌러도 이펙트 없음. 화살 이동 속도·회수 범위·판정은 바뀌지 않음.

## 포탈 · 랜덤 맵 테스트 (`TutorialBossMap_Test` ↔ `RandomMap_Test`)

튜토리얼 보스맵 테스트 씬의 문으로 들어갈 때마다 새 랜덤 맵을 만들고, 랜덤 맵의 복귀 문으로 돌아온다. 전투·아이템·적 없음.

- 흐름: `TutorialBossMap_Test` 왼쪽 높은 지면의 문(`Portal_RandomMap`, x 8) → 가까이 가면 'W키로 입장' → W → `RandomMap_Test` 를 열고 새 시드로 맵 생성 → 맵 끝의 복귀 문(`Portal_Return`, 'W키로 돌아가기') → W → 튜토리얼 씬의 문 오른쪽에 도착 → 다시 입장하면 새 시드
- 씬 방식: 두 씬은 각자 플레이어(기존 프리팹 인스턴스)·카메라를 하나씩 가지고 `LoadSceneMode.Single` 로 바뀐다. 씬이 바뀌면 이전 씬의 맵·플레이어가 함께 사라져 중복이 생기지 않는다. 씬 사이에 남는 것은 `PortalTravel`(정적: 이동 중 여부·다음 시드·도착 포탈 id)뿐
- 에디터에서는 `EditorSceneManager.LoadSceneAsyncInPlayMode` 로 경로를 바로 열어 Build Settings 를 바꾸지 않았다. 빌드에서 쓰려면 두 씬을 Build Settings 에 넣어야 한다(본편 `LaurelBuilder` 는 `Laurel_Main` 만 빌드하므로 영향 없음)
- 포탈(`Scripts/World/RandomMap/ScenePortal.cs`): 범위 = 문 바닥 기준 위 1.2 중심 ±1.4×±1.6. 범위 밖이면 W 무시, 누르면 `PortalTravel.Loading` 이 켜져 씬이 바뀔 때까지 추가 입력 무시(키 한 번 = 이동 한 번), 이동 중 조작 정지. 그림은 런타임 도형(아치 + 빛), 안내 글자는 IMGUI(검정 외곽선). W 는 기존 조작에 쓰지 않는 키
- 생성(`RandomMapAlgorithm.cs`, 옆에서 보는 플랫포머용):
  1. 지면: 좌→우 구간(폭 4~10칸)마다 높이 랜덤 워크. 오르막은 최대 3칸(한 번 점프로 오름), 내리막 최대 4칸, 시작 구간은 8칸 평지
  2. 공중 발판(두께 2): 아래 지형에서 점프로 닿는 높이에 무작위로 놓고, 아래 4칸·좌우 2칸·위 4칸을 비워 둠(Rule Tile 모서리가 붙지 않게)
  3. 도달 판정: 설 수 있는 칸(아래가 지형, 위 2칸 빔)을 노드로, 걷기·점프(위 6칸·옆 6칸 이내, '제자리 상승 후 옆 이동' 경로가 비어 있을 때)·낙하('옆 이동 후 하강') 간선으로 BFS. 실제 점프(한 번 ≈ 7.5칸, 2단 ≈ 12칸)보다 보수적. 시작 지점에서 못 가는 발판은 지움
  4. 복귀 포탈: 시작 → 포탈, 포탈 → 시작 모두 갈 수 있는 칸 중 가장 먼 평지(좌우 1칸도 평지, 머리 위 3칸 빔)
